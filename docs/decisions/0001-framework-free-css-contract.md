# 0001. Keep styling in plain CSS, tied to components by an anatomy comment

## Status

Accepted on 2026-10-16, when the design spec was approved.

## Context

kbui serves several React projects today, and one day it might need to serve something that isn't React. If the styles lived inside the React package, as CSS Modules, CSS-in-JS or Tailwind classes, a second framework would mean restyling everything from scratch.

This only pays off if a second framework actually shows up. If every project stays on React, we've added a little indirection for nothing.

## Decision

All visual styling lives in `@kbui/css` as plain CSS. Each component has one root class, `kb-<name>`, its parts are `kb-<name>-<part>`, and variants and states are `data-*` attributes. The first line of each stylesheet is an `Anatomy:` comment that lists exactly those, and on the styling side, the React package only renders that markup. It doesn't import any CSS.

A test in `packages/css/src/build.test.ts` fails if a stylesheet is missing its anatomy line, or if it never styles the root class it names.

## Options considered

- We accepted plain CSS with `kb-` classes and `data-*` attributes. It has no runtime cost, any framework can render it, and it sits happily next to a project's own Tailwind.
- CSS Modules inside `@kbui/react` were rejected. The class names are generated by the JavaScript bundler, so another framework would have to start over.
- Tailwind with class variants was rejected because every project would then need Tailwind, configured to scan kbui's files.
- CSS-in-JS was ruled out for its runtime cost and its tie to React.

## Consequences

Each component is now two files that have to agree, the stylesheet and the React component, and the only thing linking them is a comment.

Projects have to import `@kbui/css/styles.css` themselves. If they forget, the components render unstyled.

Specificity is kept flat, so overriding a style takes either a more specific selector or an equally specific one that loads later.

## Soundness boundary

The test checks that the anatomy line exists and that its root class is styled. It doesn't check that every part and attribute in the line is styled, or that the React component really renders them. Each component's own tests are the only cover for that.

## Threat model

This protects against the layers drifting apart, and against styles that only one framework can use. It does nothing to stop a project overriding kbui's variables or classes in its own CSS.

## Non-goals

- Building a non-React adapter now.
- Isolating styles with shadow DOM or similar.

## Revisit if

- A project needs kbui inside a shadow root or an iframe that global CSS can't reach.
- Keeping the anatomy line and the React output in step keeps causing bugs.

## Adoption

`Button`, `Input` and `Dialog` all follow it, and the component generator writes the anatomy line first.

## Validation

- Done: `bun test --cwd packages/css` passed the anatomy and palette tests at commit 2a5fd82.
- Done: the same suite includes cases with a missing anatomy line and an unstyled root class, added in commit 3a289d6, and both are rejected as they should be.
